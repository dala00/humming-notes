# Humming Notes

鼻歌を録音して楽器の演奏に変換し、重ね録りで曲にするスキル。役割分担は次のとおり。

- **ブラウザのページ**: マイク録音、音程解析（鼻歌 → ノート）、再生、重ね録り、ピアノロールでの手直し、MP3 / WAV のレンダリング。
- **ローカルサーバー**（`scripts/humming.mjs`、依存なしの Node 18+）: ページの配信、`project.json` の保存、楽器音色のダウンロードとキャッシュ、書き出しファイルの保存。
- **Claude（あなた）**: サーバーの起動、録音の清書（音高曲線を読んで丁寧にノート化し直す）、ユーザーの言葉を受けて `project.json` を直接編集（楽器の指定、移調、クオンタイズ、音の修正、ハモリや伴奏トラックの作曲）、書き出しコマンドの実行。

ページと Claude は同じ `project.json` を共有する。Claude がファイルを書き換えると、ページは約 1.5 秒以内に自動で読み込み直す。

## 起動

スクリプトはこの SKILL.md と同じフォルダの `scripts/humming.mjs`。バックグラウンドで起動する（`run_in_background: true`）。

```bash
node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" serve --project "<プロジェクトフォルダ>" --open
```

- `--project` は曲ごとのフォルダ。省略時はカレントの `humming-projects/default`。ユーザーが曲名を言ったら `humming-projects/<曲名>` にする。
- `--open` で既定のブラウザに `http://localhost:4173/` が開く。ポートを変えるときは `--port`（以降のコマンドにも同じ `--port` を付ける）。
- 「ポートは使用中」と出たら、すでに起動済みの可能性が高い。`status` で確認し、同じプロジェクトならそのまま使う。
- マイクの許可はユーザーがブラウザで行う。Claude が代わりに録音することはできない。

起動したらユーザーに次を短く伝える。

1. 「次の録音の楽器」を選び（Claude に言ってもよい）、「● 録音」を押す。カウントインのあと鼻歌を歌い、もう一度押すとノートに変換される。
2. 「▶ 再生」で確認。もう一度「● 録音」を押すと、今ある演奏を聞きながら次のパートを重ねられる。重ね録りはヘッドホン推奨。
3. 直したいことや足したいパートは Claude に言葉で頼める。最後に「MP3 にして」で書き出せる。

録音の進め方は 2 通りあり、ページの「下書き録音」チェックで切り替わる。精度を求めるなら下書き録音を勧める。

- **下書き録音（おすすめ）**: 録音は楽器音にせず、自分の生声のまま重ねていく。各パートには「変換後」の楽器だけ指定しておく。録り終えたら Claude に「まとめて変換して」と頼む。変換前の間違った音につられずに歌え、Claude は全パートを見比べて調とリズムを決められる。
- **即時変換**: 録音のたびにページが機械的に楽器のノートへ変換する。すぐ楽器音で聞けるが粗い。あとから「清書して」で直せる。

2 つ目の録音が終わった時点で、ページが最初の 2 つを比べて重ね録りの遅延を自動で計測・補正する（結果はページに表示される）。

## 状態を見る

```bash
node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" status
```

プロジェクトの場所、ページが開いているか、トラック一覧、書き出し済みファイルが JSON で返る。ノートの中身を見るときは `project.json` を直接読む。

## project.json の編集

ユーザーの依頼の大半は `project.json` の編集で応える。編集前に必ず最新のファイルを読む（ユーザーがページで録音や手直しをしている）。ユーザーが録音中のときはページ側が読み込みを待つので、編集してよい。

```jsonc
{
  "name": "曲名",            // 書き出しファイル名に使う
  "bpm": 100,                // メトロノーム、小節線、クオンタイズ、MIDI のテンポ
  "beatsPerBar": 4,
  "metronome": true,
  "countInBars": 1,          // 録音前のカウントイン小節数
  "latencyMs": 0,            // 重ね録りのずれ補正（録音が遅れて聞こえるなら増やす）
  "snapToScale": true,       // ページの機械変換で、調から外れた曖昧な音を調に寄せる
  "draft": false,            // 下書き録音（生声で重ね、あとでまとめて変換）
  "latencyCalibrated": false,// 遅延の自動計測が済んだか
  "soundfont": "MusyngKite", // 音源セット。MusyngKite（高音質）/ FluidR3_GM（標準）/ FatBoy
  "reverb": 0.2,             // 響きの量。0 でなし、0.6 でかなり深い
  "reverbTime": 1.8,         // 響きが消えるまでの秒数。小部屋 0.6、ホール 2.5 程度
  "next": { "instrument": "flute" },   // 次の録音に使う楽器
  "tracks": [
    {
      "id": "t1",            // 一意。新規トラックは重複しない ID を付ける
      "name": "メロディ",
      "instrument": "flute", // 下記の楽器名。"voice" は録音した生声をそのまま鳴らす
      "volume": 0.8,         // 0〜1.5
      "mute": false,
      "transpose": 0,        // 半音単位。オクターブは ±12
      "quantize": 0,         // 1 拍の分割数。0=なし 1=4分 2=8分 3=3連 4=16分（鳴らすときだけ適用、元のノートは保持）
      "offsetMs": 0,         // トラック全体を前後にずらす
      "pan": 0,              // 左右の位置。-1 左、0 中央、1 右
      "humanize": 0,         // 0〜1。タイミングと強さに人間らしい小さな揺らぎを足す
      "take": "takes/t1.wav",// 元の録音。消さない。Claude が作ったトラックは null
      "original": null,      // 清書前のノート。set-notes が自動で入れる。手で触らない
      "planned": null,       // 下書きトラックが変換後になる予定の楽器
      "notes": [ { "t": 0.52, "d": 0.31, "p": 64, "v": 0.8 } ]
    }
  ]
}
```

- ノートの `t` は開始秒、`d` は長さ秒、`p` は MIDI ノート番号（60 = 中央のド）、`v` は強さ 0〜1。1 拍は `60 / bpm` 秒。
- **楽器名**は General MIDI の名前（`scripts/shared.mjs` の `GM_NAMES` にある 128 種）。よく使うもの: `acoustic_grand_piano` `electric_piano_1` `music_box` `vibraphone` `marimba` `church_organ` `accordion` `acoustic_guitar_nylon` `acoustic_guitar_steel` `electric_guitar_clean` `distortion_guitar` `acoustic_bass` `electric_bass_finger` `synth_bass_1` `violin` `cello` `string_ensemble_1` `choir_aahs` `trumpet` `trombone` `alto_sax` `clarinet` `flute` `ocarina` `whistle` `lead_1_square` `lead_2_sawtooth` `pad_2_warm` `koto` `shamisen` `steel_drums`。一覧にない名前を書くと簡易シンセ音になる。
- 音色は初回だけネットから取得し `~/.cache/humming-notes/` にキャッシュする。オフラインで未取得の楽器は簡易シンセ音になる。

### よくある依頼と編集

| 依頼 | 編集 |
| --- | --- |
| 「次はベースで録る」 | `next.instrument` を `acoustic_bass` などに |
| 「2 番目をバイオリンにして」 | そのトラックの `instrument` |
| 「オクターブ下げて」 | `transpose` を -12 |
| 「リアルにして」「音を良くして」「響きを足して」 | 下の「音作り」を参照 |
| 「リズムを揃えて」 | `quantize` を 2 か 4。先に `bpm` が歌のテンポに合っているか確認する |
| 「清書して」「変換が雑」「音が違う」「まとめて変換して」 | 下の「清書」の手順で音高曲線から変換し直す |
| 「下書きモードにして」「生声で重ねたい」 | `draft` を true に |
| 「ハモリを足して」 | メロディのノートを複製し、調に合う 3 度・6 度へ移した新トラックを追加 |
| 「伴奏／ベース／コードを付けて」 | メロディから調とコード進行を推定し、小節に合わせた新トラックを作曲して追加 |
| 「重ね録りがずれる」 | まず `latency` コマンドで計測し、信頼できる結果なら `--apply`。だめなら `offsetMs` や `latencyMs` を聞きながら調整 |

新しいトラックを作曲するときは、既存ノートの時間（秒）と `bpm` から拍・小節を割り出して合わせる。鼻歌がメトロノームなしで歌われていてテンポが合っていない場合は、ノートの間隔から `bpm` を推定して設定してから作る。編集後は何を変えたかを一言で伝え、再生して確認してもらう。

和音は同じトラックに同じ `t` のノートを並べればよい。

## 音作り（リアルに聞かせる）

Claude は音を聞けない。数値と定石で設定し、ユーザーの感想で調整する。一度に大きく変えず、何を変えたかを伝える。

- **音を響かせる**: ギター、ピアノ、ハープなど弾いたあと自然に減衰する楽器は、ノートの `d` を伸ばして鳴らしっぱなしにする。アルペジオは各音を次のコードの頭の直前まで、メロディは次の音の頭の直前まで（上限 1.6 秒程度）。管楽器や弦の持続音は歌われた長さのままにする。
- **定位**: 主旋律は中央（`pan` 0）、ハモリや伴奏は左右に ±0.3〜0.5 で振り分ける。ベースは中央。
- **揺らぎ**: `humanize` 0.3〜0.5。格子に置いたノートの機械っぽさが減る。
- **響き**: `reverb` 0.15〜0.3 が標準。バラードやアコースティックは `reverbTime` 2 秒前後、速い曲は 1 秒前後。濁ると言われたら `reverb` を下げる。
- **音源**: `soundfont` は `MusyngKite` が既定で最も自然。初回は楽器ごとに数 MB を取得する。
- **音量バランス**: 主旋律を 0.8〜0.9、伴奏を 0.5〜0.7 に。

大きく作り変える前に `project.json` を同じフォルダへコピーして退避しておく。

## 清書（録音を丁寧に変換し直す）

ページの変換は機械的で、1 音ずつ近い半音に丸めるだけ。鼻歌の揺れ、しゃくり、リズムのよれがそのままノートになる。ユーザーが「清書して」「丁寧に変換して」「変換が雑」「音が違う」などと言ったら、Claude が歌の音高曲線を読んで、歌い手の意図を解釈し直す。これがこのスキルで Claude が最も価値を出す作業。

「まとめて変換して」（下書き録音のあと）も同じ作業で、全トラックを一度に読んでから決める点と、楽器を切り替える点だけが違う。

### 手順

1. `status` でトラックを確認する。`instrument` が `voice` で `planned` があるものは下書き（未変換）。対象の指定がなければ、録音（`hasTake`）があり未清書（`cleaned` が false）の全トラックが対象。
2. 録音が 2 つ以上あれば、重ね録りのずれが残っていないか確かめる。

   ```bash
   node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" latency --project "<プロジェクトフォルダ>"
   ```

   ±30ms を超えるずれが報告されたら `--apply` を付けて反映する（`latencyMs` と未清書トラックの `offsetMs` が補正される）。「計測できませんでした」なら何もしない。
3. 音高曲線を出す。`--track` を省くと録音のある全トラックが出るので、まとめて変換のときは必ず全部を一度に読む。

   ```bash
   node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" curve --project "<プロジェクトフォルダ>" [--track <id|番号|名前>]
   ```

   30ms ごとの「音高（MIDI 番号の小数）/ 音量 0〜9」がフレーズ単位で出る。全体のチューニングずれは差し引き済み。時刻は曲の時刻（`offsetMs` 適用後）。長い曲は `--from` `--to`（秒）で 30〜60 秒ずつ区切って読む。
4. 先に曲全体の方針を決める: 調、テンポと拍の格子、フレーズの繰り返し構造、パート同士の関係（同じ箇所で何を歌っているか）。そのうえで下の判断基準で各トラックのノート列を決める。
5. トラックごとに `[{"t":0,"d":0.23,"p":43,"v":0.8}, ...]` の JSON をスクラッチ用の場所に書き、適用する。`t` は曲の時刻で書く。

   ```bash
   node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" set-notes --track <id> --notes <file.json> --project "<プロジェクトフォルダ>" [--instrument <楽器名>]
   ```

   下書きトラックは `--instrument` に `planned` の楽器を渡して生声から楽器へ切り替える（`planned` が未定ならパートの音域と役割から選び、選んだ楽器を伝える）。清書前のノートは自動で `original` に退避される。ユーザーはページの「清書前と入れ替え」ボタンで聞き比べられ、`restore --track <id>` で戻せる。生声に戻したいときは楽器を「生声」に変えればよい。
6. 何をどう解釈したか（調、テンポ、各パートの形）と、判断に迷った箇所を具体的に（何小節目のどの音か）伝え、再生して確認してもらう。違うと言われた箇所だけ直す。

### 判断基準

- **1 音は平らな部分で決める。** 音の頭のしゃくり上げ、着地前の行き過ぎ、次の音へ向かう終わりの滑りは別の音にしない。平らな部分（プラトー）の中央値がその音。
- **リズムは曲線の音の立ち上がり位置で決める。** `bpm` から拍の秒数を出し、立ち上がりが 8 分や 16 分の格子に ±0.06 秒程度で乗っているなら格子に置く。全体が一定量ずれているだけなら格子に合わせる。格子に乗らない歌い方（ルバート、テンポ未設定）は無理に合わせず、相対的な長さを整える程度にする。メトロノームなしで歌われていたら、先に立ち上がりの間隔から `bpm` を推定して設定する。
- **繰り返しを探す。** 同じ形のフレーズが何度も出るなら、曖昧な音は明瞭に歌われた回に合わせる。ただし、毎回安定して違う音で歌われている箇所は意図的な変化なので残す。
- **調は全トラックを見てから決める。** 1 トラックだけで判断しない。メロディとベースで合わせて読むと短調の属和音など別の解釈が成り立つことがある。機械の「調の推定」は参考程度。
- **歌われた音を優先する。** 半音の真ん中（小数部が .4〜.6）の音だけ、調・繰り返し・その人の外し方の傾向（低音で下がる、など）で決める。安定して伸ばされた音は、調から外れていても直さない。理屈に合わせて曲を作り替えない。
- **息や子音で途切れた同じ高さの断片は 1 音にまとめる。** ただし、音量がはっきり落ちてから同じ高さで鳴り直しているものは、歌い直し（同音連打）として分ける。
- **長さ**は、次の音の頭の少し手前まで（スタッカート気味に歌われていれば短く）。フレーズ最後の伸ばしは実際の長さを尊重する。
- **強さ `v`** は音量の列を参考に 0.6〜1.0 でつける。迷ったら 0.8。
- **オクターブ飛び**（突然 ±12 前後動いてすぐ戻る）は検出ミスなので、周囲に合わせる。
- **パート同士を突き合わせる。** 同じ箇所で、あるパートの曖昧な音は他のパートと協和するほうを選ぶ。全パートが一定量（半音など）ずれて噛み合わない場合は、歌い手が基準を取り違えた可能性をユーザーに伝え、勝手に移調しない。
- `set-notes` は `quantize` を 0 に戻す（格子に置いたノートを二重に丸めないため）。

清書は推測を含む。直した量が多いときほど、迷った箇所を正直に伝える。

## 書き出し

```bash
node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" export mp3    # または wav
node "${CLAUDE_SKILL_DIR}/scripts/humming.mjs" midi --project "<プロジェクトフォルダ>"
```

- `export` は開いているページに音声をレンダリングさせ、`<プロジェクト>/exports/` に保存してパスを表示する。ページのタブが開いている必要がある。タイムアウトしたら、タブを前面にしてもらうか、ページの「MP3 書き出し」ボタンを押してもらう（同じ場所に保存され、ブラウザにもダウンロードされる）。
- `midi` はページ不要で `project.json` から直接作る。ミュート中のトラックは含まれない。`voice` トラックは検出済みノートとして出力される。
- 書き出したら保存先のパスをユーザーに伝える。

## うまくいかないとき

- **ノートが検出されない／音が違う**: マイクに近づき「ラ」「ナ」などではっきり歌ってもらう。息の多いハミングや周囲の雑音は苦手。スピーカーで伴奏を流しながらの録音は伴奏を拾うのでヘッドホンにする。
- **Bluetooth ヘッドホンで大きくずれる**: 遅延が大きい。自動計測が拾えるのは ±300ms まで。有線にするか `latencyMs` を手で 150〜250 程度に上げる。
- **遅延の自動計測が外れた**: リズムが単純すぎる、または 2 つのパートの音の頭が対応していないと誤ることがある。ユーザーはページで Ctrl+Z、Claude は `latencyMs` と `offsetMs` を戻す。
- **ページが「外部で更新された」と言う**: 正常。Claude の編集を読み込んだだけ。
- **解析ロジックの確認**: `node "${CLAUDE_SKILL_DIR}/scripts/selftest.mjs"` で合成した鼻歌に対する変換テストが走る。
